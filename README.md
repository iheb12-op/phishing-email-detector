# Phishing Email Detector

Educational, **defensive** SOC-style tool for analyzing suspicious emails:
paste raw email text or upload a `.eml` file and get an explainable risk
score, categorized findings, extracted URLs/attachments, and MITRE ATT&CK
mapping — rendered on a dark SOC-style dashboard.

## Architecture

```
Frontend (Next.js/TS)  -->  REST API  -->  Spring Boot Backend  -->  Analysis Engine  -->  PostgreSQL
```

## Prerequisites

- Java 21+ and Maven (or use the `./mvnw` wrapper once generated by your IDE)
- Node.js 18+
- Docker (for PostgreSQL)

## Architecture

```
ParsedEmail (EmailParser: Jakarta Mail for .eml, regex fallback for pasted text)
      │
      ├── HeaderAnalyzer      (SPF/DKIM/DMARC, Reply-To mismatch)
      ├── SenderAnalyzer      (display-name/domain mismatch, lookalike sender)
      ├── UrlAnalyzer         (link/href mismatch, IP URLs, shorteners, punycode)
      ├── AttachmentAnalyzer  (double extensions, macros, archives)
      ├── ContentKeywordAnalyzer (urgency/credential-theft language)
      └── HtmlAnalyzer        (iframes, hidden elements, embedded forms, tracking pixels)
                │
                ▼
        RiskScoringEngine  →  MitreAttackMapper
                │
                ▼
     EmailAnalysisService (persists EmailAnalysis + children to PostgreSQL)
                │
                ▼
        AnalysisController (REST API)  →  Next.js SOC Dashboard
```

## Running the project (no Docker required)

By default the backend uses an embedded H2 file database — nothing to
install or start beforehand.

### 1. Start the backend

```bash
cd backend
mvn spring-boot:run
```

On first run, Flyway creates the schema automatically in a local file at
`backend/data/phishingdb.mv.db`. Verify it's up:
`curl http://localhost:8080/api/health` should return `{"status":"UP",...}`

### 2. Start the frontend

```bash
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

Open http://localhost:3000 — paste a raw email or upload one of the files
in `samples/` to see the full SOC dashboard.

### 3. Run backend tests

```bash
cd backend
mvn test
```

### Optional: use PostgreSQL instead of H2

If you'd rather use a real PostgreSQL database (e.g. before deploying):

```bash
docker compose up -d postgres
cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=postgres
```

### 4. Try it with the sample emails

`samples/` contains five synthetic emails (safe to use — no real credentials
or live malicious infrastructure):

## API endpoints

- `POST /api/analyze/email` — analyze pasted raw email text (`{"rawEmail": "..."}`)
- `POST /api/analyze/eml` — analyze an uploaded `.eml` file (multipart `file`)
- `GET /api/analysis/{id}` — retrieve a past analysis
- `GET /api/analysis/{id}/findings` / `/urls` / `/attachments` — sub-resources
- `GET /api/stats` — aggregate verdict breakdown and average risk score
- `GET /api/health` — liveness check

## Configuration

- `backend/src/main/resources/scoring-weights.yml` — per-severity score weights and verdict thresholds
- `backend/src/main/resources/trusted-domains.yml` — trusted-domain list used for lookalike/typosquatting detection

## Security notes (apply throughout the whole project)

- Every uploaded email is treated as **untrusted input**.
- No attachment is ever executed or content-scanned — only declared metadata (filename, MIME type, size) is analyzed.
- No JavaScript inside HTML emails is ever executed — Jsoup parses HTML as inert markup only.
- No URL found inside an analyzed email is ever fetched automatically.
- Uploads are capped at 10MB; `.eml` extension and basic path-traversal checks are enforced.
- Per-IP rate limiting (20 requests/min) on `/api/analyze/*`.
- Errors never leak stack traces or internal details to the client.

## Honest notes on what was verified in this build

- **Frontend**: `npm install` and `npm run build` were both run successfully in the
  build environment — the TypeScript/React code compiles and `npm audit` reports
  **0 vulnerabilities** (Next.js was pinned to 15.5.24 to fix a critical AVIF RCE,
  and a `postcss` override was added to clear a nested vulnerable copy).
- **Backend**: the build environment has no Maven and no network access to Maven
  Central, so `mvn test` could **not** be executed here. All 51 Java files were
  checked for brace/structural balance and reviewed manually, but you should run
  `mvn test` yourself before relying on this in a portfolio — see "Running the
  project" above.
